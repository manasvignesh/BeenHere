# BeenHere v1.1.0 — Research Beyond the Obvious

BeenHere is an open-source Agent Skill that helps developers and coding agents discover existing products, reusable code, academic research, cross-industry approaches, licensing obligations, and build-versus-reuse opportunities before writing software.

BeenHere v1.1.0 expands the skill from single-repository inspection into a multi-angle research system featuring cross-industry algorithmic transfer analysis, multi-candidate repository comparison, and automated integration blueprints.

---

## What's New in v1.1.0

### Cross-Industry Research Intelligence
Discovers candidate engineering approaches from outside a developer's immediate product category, checks their assumptions, and evaluates whether they can practically transfer:
- **Underlying Mechanism Extraction:** Dissects high-level product pitches into core computational and operational primitives.
- **Anti-Buzzword Filtering:** Rejects superficial analogies (such as beehives or courtroom trials) while surfacing genuine algorithmic transfers (e.g., CRDTs, Gale-Shapley stable matching, Hungarian assignment, or Bayesian rating systems).
- **8-Dimension Transferability Audit:** Systematically evaluates candidate solutions across problem equivalence, input compatibility, output suitability, operational constraints, hidden assumptions, integration practicality, engineering risk, and evidence strength.
- **Negative-Control Screening:** Triggers `NO_TRANSFER_NEEDED` on standard architectures (like simple CRUD applications) to avoid overengineering.
- **Standardized Output Postures:** Classifies transfers into `TRANSFERABLE_IMPLEMENTATION`, `TRANSFERABLE_ALGORITHM`, `TRANSFERABLE_ARCHITECTURAL_PATTERN`, `CONCEPTUAL_INSPIRATION`, `REQUIRES_VALIDATION`, or `NOT_TRANSFERABLE`.

### Intelligent Repository Comparison
Evaluates two or more open-source repositories side-by-side to assist in build-versus-reuse decisions:
- Compares real functional overlap, maintenance activity, exported interface surfaces, and dependencies.
- Assigns defensible recommendation postures: `ADOPT_AS_DEPENDENCY`, `FORK_AND_CUSTOMIZE`, `VENDOR_SUBSET`, `REIMPLEMENT_CLEANROOM`, `INTEGRATE_VIA_ADAPTER`, `REJECT_INCOMPATIBLE`, or `BUILD_CUSTOM`.
- Features qualified legal risk handling distinguishing confirmed license text from architectural or jurisdictional interpretations.

### Actionable Integration Blueprints
Transforms repository comparison findings into practical architecture guidance:
- Outlines architectural boundaries and integration requirements.
- Generates concrete, proposed Anti-Corruption Adapter contracts (TypeScript and Python interface stubs).
- Defines step-by-step verification protocols and highlights unresolved technical uncertainties.

### Improved Research Reliability
- **Hardened Concept Expansion:** Employs 4-tier query matrices, morphological fallbacks, and deduplicated search queries to prevent empty results on unfamiliar topics.
- **Strict Evidence Provenance:** Distinguishes verified implementation evidence (`[VERIFIED-SOURCE]`, `[VERIFIED-TEST]`) from marketing statements (`[UNVERIFIED-MARKETING-CLAIM]`) and inferences (`[INFERRED]`).
- **Anti-Percentage Rule:** Strictly rejects arbitrary, ungrounded reusability percentages in favor of qualitative, evidence-backed evaluation.

## Known Limitations

- **Coding-Agent Sandbox Subshells:** Some agent sandboxes (such as certain restricted subshell profiles in OpenAI Codex) restrict child-process Python execution or network sockets. The documented **Host-Agent Fallback Mode** in `SKILL.md` handles these situations by allowing agents to inspect pre-generated evidence and invoke native host tools.
- **Source Inspection Scope:** Automated static analysis inspects manifests, AST symbols, and exported interfaces, but cannot guarantee full runtime compatibility across unverified dependencies or heterogeneous system environments.
- **Legal Compliance:** License detection and copyleft obligation assessments are informational engineering analyses, not formal legal advice.
- **Benchmarking & Superiority Disclosures:** BeenHere evaluations demonstrate qualitative structured discovery and verification traps. No independently verified numerical superiority over baseline coding agents is claimed.

## Installation & Usage

Install into your AI coding assistant using the Agent Skills CLI:

```bash
# Install for Claude Code, Codex, or all agents:
npx skills add manasvignesh/BeenHere --agent claude-code codex
```

Or use the standalone zero-dependency installer:

```bash
python scripts/install_skill.py
```

Activate BeenHere in your assistant with:
- `/beenhere <idea>` for rapid initial exploration.
- `/beenhere --deep <idea>` for full prior-art landscapes and integration blueprints.
